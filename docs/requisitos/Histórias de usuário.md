# Histórias de usuário — Nhe’engaTupi (Backlog v2 + Histórico v1)

## Parte 1 — Backlog v2 Consolidado (Escopo Funcional de Referência — US01 a US11)

1. **US01 — Acessar lições básicas (Prioridade: Alta):** Como estudante, quero acessar lições básicas de Tupi organizadas para aprendizagem progressiva, para estudar vocabulário e conteúdos introdutórios.
2. **US02 — Responder quizzes (Prioridade: Alta):** Como estudante, quero responder quizzes relacionados às lições, para verificar minha compreensão e receber retorno sobre minhas respostas.
3. **US03 — Conhecer história e cultura indígena (Prioridade: Alta):** Como estudante, quero consultar conteúdos sobre história e cultura indígena com contexto e fontes identificadas, para ampliar meu conhecimento de forma responsável.
4. **US04 — Ouvir áudios das palavras em Tupi (Prioridade: Alta):** Como estudante, quero reproduzir o áudio associado às palavras em Tupi, para ter apoio auditivo durante o estudo da pronúncia.
5. **US05 — Acompanhar progresso (Prioridade: Alta):** Como estudante, quero visualizar meus registros de aprendizagem, para acompanhar as lições e atividades concluídas.
6. **US06 — Revisar palavras e lições anteriores (Prioridade: Alta):** Como estudante, quero reabrir palavras e lições que já estudei, para revisar conteúdos e retomar minha aprendizagem.
7. **US07 — Baixar lições para estudar sem internet (Prioridade: Média):** Como estudante, quero baixar lições compatíveis com uso offline, para estudar mesmo quando estiver sem conexão.
8. **US08 — Receber pontos e cumprir metas (Prioridade: Média):** Como estudante, quero acompanhar pontos e metas de estudo, para visualizar minha evolução e organizar minha rotina de aprendizagem.
9. **US09 — Consultar dicionário Tupi-Português (Prioridade: Alta):** Como estudante, quero pesquisar palavras em um dicionário Tupi-Português, para consultar seus significados e informações complementares disponíveis.
10. **US10 — Acessar conteúdos Premium (Prioridade: Média):** Como pessoa usuária, quero consultar os benefícios, preços e condições dos conteúdos Premium, para decidir se desejo contratar esse acesso.
11. **US11 — Visualizar frases cotidianas (Prioridade: Alta):** Como estudante, quero consultar frases cotidianas organizadas por categoria, para conhecer exemplos de expressões e seus contextos de uso.

# Backlog do Produto — v1 (18 Histórias — Histórico Preservado)

O backlog reúne 18 histórias de usuário funcionais para o aplicativo Nhe’engaTupi. As histórias foram recebidas como material da equipe e da IA; os critérios de aceitação descrevem comportamentos esperados, não funcionalidades já implementadas.

## US01 — Cadastro de usuário

**User Story:** Como usuário, quero criar uma conta no aplicativo para ter acesso ao meu progresso e às funcionalidades de aprendizagem.

**Critérios de aceitação**

- O usuário deve conseguir realizar seu cadastro.
- O sistema deve solicitar os dados necessários para criar a conta.
- O sistema deve informar caso algum dado obrigatório não seja preenchido.
- Após o cadastro, o usuário deve conseguir acessar o aplicativo.

**Fonte:** IA + equipe

## US02 — Acesso à conta

**User Story:** Como usuário, quero entrar na minha conta para continuar meus estudos e acompanhar meu progresso.

**Critérios de aceitação**

- O usuário deve conseguir informar seus dados de acesso.
- O sistema deve validar os dados.
- Caso estejam incorretos, o sistema deve informar o erro.
- Caso estejam corretos, o usuário deve ter acesso à sua conta.

**Fonte:** IA + equipe

## US03 — Módulos de vocabulário

**User Story:** Como estudante, quero acessar módulos de vocabulário Tupi para aprender novas palavras de forma organizada.

**Critérios de aceitação**

- Os módulos devem apresentar conteúdos de vocabulário.
- As lições devem ser curtas e estruturadas.
- O usuário deve conseguir avançar entre as lições.
- O sistema deve registrar o progresso do usuário.

**Fonte:** IA + equipe

## US04 — Módulos de gramática

**User Story:** Como estudante, quero estudar gramática Tupi por meio de lições interativas para melhorar meu aprendizado.

**Critérios de aceitação**

- O sistema deve disponibilizar conteúdos de gramática.
- As lições devem ser organizadas em módulos.
- O usuário deve conseguir acompanhar seu progresso.
- O conteúdo deve ser apresentado de maneira interativa.

**Fonte:** IA + equipe

## US05 — Conteúdos históricos e culturais

**User Story:** Como usuário, quero acessar informações históricas e culturais relacionadas à língua Tupi para conhecer melhor essa herança cultural.

**Critérios de aceitação**

- O aplicativo deve apresentar conteúdos históricos e culturais.
- Os conteúdos devem estar relacionados aos módulos de aprendizagem.
- O usuário deve conseguir acessar essas informações durante seus estudos.

**Fonte:** IA + equipe

## US06 — Quizzes

**User Story:** Como estudante, quero responder quizzes para verificar se compreendi os conteúdos estudados.

**Critérios de aceitação**

- O sistema deve apresentar perguntas relacionadas ao conteúdo estudado.
- O usuário deve conseguir responder às perguntas.
- O sistema deve informar o resultado ao final.
- O resultado deve contribuir para o acompanhamento do aprendizado.

**Fonte:** IA + equipe

## US07 — Pontuação

**User Story:** Como usuário, quero receber pontos ao realizar atividades para acompanhar meu desempenho no aplicativo.

**Critérios de aceitação**

- O sistema deve atribuir pontos conforme a realização das atividades.
- A pontuação deve ser armazenada na conta do usuário.
- O usuário deve conseguir visualizar sua pontuação.

**Fonte:** IA + equipe

## US08 — Progresso de aprendizagem

**User Story:** Como estudante, quero acompanhar meu progresso para saber quanto já avancei no aprendizado.

**Critérios de aceitação**

- O sistema deve registrar as atividades realizadas.
- O usuário deve conseguir visualizar seu progresso.
- O progresso deve ser atualizado após a conclusão das atividades.

**Fonte:** IA + equipe

## US09 — Recompensas

**User Story:** Como usuário, quero receber recompensas ao cumprir atividades para me manter motivado a continuar estudando.

**Critérios de aceitação**

- O sistema deve disponibilizar recompensas relacionadas ao progresso.
- O usuário deve receber a recompensa quando cumprir os requisitos.
- As recompensas conquistadas devem ficar registradas.

**Fonte:** IA + equipe

## US10 — Ranking

**User Story:** Como usuário, quero visualizar um ranking para comparar minha pontuação com a de outros usuários.

**Critérios de aceitação**

- O sistema deve apresentar um ranking.
- A posição deve considerar a pontuação dos usuários.
- A pontuação deve ser atualizada conforme novas atividades forem realizadas.

**Fonte:** IA + equipe

## US11 — Certificado digital

**User Story:** Como estudante, quero receber um certificado digital ao concluir módulos avançados para comprovar minha conclusão.

**Critérios de aceitação**

- O sistema deve identificar a conclusão dos módulos necessários.
- O certificado deve ser gerado digitalmente.
- O usuário deve conseguir visualizar seu certificado.
- O certificado deve estar disponível após a conclusão dos requisitos.

**Fonte:** IA + equipe

## US12 — Comunidade online

**User Story:** Como estudante, quero participar de uma comunidade online para interagir com outros usuários e trocar conhecimentos culturais.

**Critérios de aceitação**

- O usuário deve conseguir acessar a comunidade.
- Deve ser possível interagir com outros estudantes.
- O espaço deve permitir troca de conhecimentos relacionados ao aprendizado e à cultura.

**Fonte:** IA + equipe

## US13 — Chatbot de suporte

**User Story:** Como usuário, quero utilizar um chatbot para tirar dúvidas técnicas e pedagógicas durante o uso do aplicativo.

**Critérios de aceitação**

- O usuário deve conseguir acessar o chatbot.
- O usuário deve conseguir enviar dúvidas.
- O chatbot deve fornecer uma resposta.
- O recurso deve auxiliar em dúvidas relacionadas ao aplicativo e aos estudos.

**Fonte:** IA + equipe

## US14 — Acessibilidade

**User Story:** Como usuário, quero utilizar o aplicativo com recursos de acessibilidade para ter uma experiência mais inclusiva.

**Critérios de aceitação**

- A interface deve seguir boas práticas de acessibilidade.
- Os elementos da tela devem ser fáceis de identificar e utilizar.
- A navegação deve ser adequada para dispositivos móveis.

**Fonte:** IA + equipe

## US15 — Segurança dos dados

**User Story:** Como usuário, quero que meus dados sejam protegidos para utilizar o aplicativo com segurança.

**Critérios de aceitação**

- O sistema deve proteger os dados dos usuários.
- O aplicativo deve seguir as boas práticas relacionadas à LGPD.
- Os dados não devem ser disponibilizados indevidamente a outros usuários.

**Fonte:** IA + equipe

## US16 — Desempenho do aplicativo

**User Story:** Como usuário, quero que o aplicativo responda rapidamente para conseguir estudar sem interrupções.

**Critérios de aceitação**

- O sistema deve suportar até 10.000 usuários simultâneos.
- O tempo de resposta deve ser inferior a 2 segundos nas condições previstas.
- O aplicativo deve manter seu funcionamento durante o uso.

**Fonte:** IA + equipe

## US17 — Aplicativo para Android e iOS

**User Story:** Como usuário, quero acessar o Nhe’engaTupi pelo meu smartphone para estudar independentemente do sistema operacional utilizado.

**Critérios de aceitação**

- O aplicativo deve funcionar em dispositivos Android.
- O aplicativo deve funcionar em dispositivos iOS.
- As principais funcionalidades devem estar disponíveis nas duas plataformas.

**Fonte:** IA + equipe

## US18 — Acompanhamento dos usuários

**User Story:** Como educador, quero acompanhar o desenvolvimento dos estudantes para compreender seu progresso no aprendizado.

**Critérios de aceitação**

- O sistema deve registrar o progresso dos usuários.
- As informações de progresso devem estar disponíveis para acompanhamento conforme as permissões definidas.
- Os dados devem auxiliar na avaliação do aprendizado.

**Fonte:** IA + equipe
